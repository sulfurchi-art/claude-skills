# 实例：一个像素对话游戏的角色是怎么画出来的

项目名叫《AGI 争霸战》：几个 AI 在台上辩论谁最接近 AGI，形式是像素风 galgame 演示。

- 画面 480×270，1 个美术像素就是 1 个屏幕像素，最后按整数倍放大；
- 角色全部由代码绘制，只有一个角色例外，它来自用户给的参考图。

## 一个角色 = 一个函数 + 一张表情表

橙色方块小怪 Clawd 是最典型的例子。它的身体按“格子”设计：12×8 格，每格 7 像素：

```js
const CBX = 24, CBY = 18, CBW = 84, CBH = 56;                     // 身体 84×56，位于 (24, 18)
const ARMS = {                                                    // 手臂姿势也是数据，随表情切换
  normal: [[CBX - 14, CBY + 28, 15, 14], [CBX + CBW - 1, CBY + 28, 15, 14]],
  up: [/* 两只手举起：两截矩形 */],
};
function base(arms) {
  const s = P.surface(134, 96);
  for (const lx of [7, 21, 56, 70]) s.fill(CBX + lx, CBY + CBH - 4, 7, 18, LEG);   // 4 条腿
  for (const r of ARMS[arms]) s.fill(...r, BODY);
  s.roundRect(CBX, CBY, CBW, CBH, 3, BODY);
  s.rim(/* 亮面 */, /* 暗面 */, { depth: 3, group: (k) => (k === BODY ? 1 : 2) });   // 身体和腿分开打光
  s.fill(CBX + 4, CBY + 3, 9, 2, GLOSS);                           // 左上角的高光条
  s.outline(LINE);
  return s;
}
const EX = {                                                      // 一个表情 = 一行参数
  happy:   { eye: 'happy', mouth: 'smile', arms: 'normal', blush: 1 },
  shocked: { eye: 'shock', mouth: 'O', arms: 'up', sweat: 1 },
  sad:     { eye: 'sad', mouth: 'frown', arms: 'down', tear: 1 },
  /* ... 共 9 种 */
};
```

各个部件的画法：

- **眼型**是一个 `switch`，每种眼型几行代码：
  - 普通：一个竖条加一个高光点；
  - 开心：^ 形；
  - 惊吓：白底加小瞳孔；
  - 生气、难过：用一个斜切的多边形表现眼睑角度。
- **嘴型**：表情的嘴型加 1~3 种说话嘴型，每发一个音节轮换一次。
- **附加物**：汗滴、眼泪、思考的省略点、星星。会动的附加物用 `frame % 2` 让它上下起伏 1 像素。

## 不同角色，不同的取巧方式

| 角色 | 造型思路 | 关键技巧 |
|---|---|---|
| GPT（西装机器人） | 头盔 + LED 面罩 | 眼睛和嘴是面罩上发光的 LED 矩形，外圈用抖动做光晕。说话时嘴是 4 种“声波”轮换。得意时戴墨镜（多边形） |
| Gemini（四色星） | 四角星 | 外形用超椭圆 \|x\|ⁿ+\|y\|ⁿ≤1（n<1 时星角向内凹）。颜色按角度在 HSV 环形渐变里取色（上红、左黄、下绿、右蓝，中心偏蓝），再用 Bayer 抖动量化到 16 色调色板。最后打光、描边，脸画在最上层 |
| DeepSeek（鲸鱼女仆） | 动漫少女 | 不硬画，用用户的参考表情表转换，见 `reference-images.md` |
| 主持人 | 一支麦克风 | 物件拟人，没有脸也能表演：靠灯光和舞台反应 |
| 台上小人（24~34 px） | 每个角色一个 Q 版 | 7 种表情：普通、开心、惊吓、难过、生气、得意、眨眼，共用一个函数 |
| 观众（30×40 剪影） | 10 种轮廓 | 填充深色后，只给“顶部边缘”换成舞台反光色，一个循环就做出逆光效果 |
| 图标（12×12） | 草莓、硬币、放大镜…… | 全部是字符画 |

**为什么造型都是几何化的？** 因为要用代码画。选造型时就避开了用几何形体画不好的东西。唯一的复杂造型（女仆）走参考图转换。

## 看图循环抓到的问题（都是“看”出来的）

| 看到的问题 | 原因 | 怎么改 |
|---|---|---|
| 全屏压暗看起来满是噪点 | 大面积用了抖动 | 全屏遮罩改用真正的半透明混合；抖动只留给小面积 |
| 聚光灯的光柱盖住了 LED 大屏 | 绘制顺序错了 | 大屏改到最后画 |
| 分屏画面压住了立绘框 | 坐标没算对 | 分屏底边上移到 150 |
| USER 的 `>` 提示符和文字重叠 | 没给文字留出缩进 | 加 12 px 缩进 |
| 名牌上的 “Gemini” 显示成 “Genini” | 位图字体烘焙时，字母 m 的左列被裁掉 | 用操作系统的渲染结果重新生成英文字形 |
| 角色肚皮周围出现一圈暗色 | 内部细节在打光之前画，被当成了“洞” | 先打光，再画内部细节 |
| 右眼比左眼偏一格 | 宽度为奇数的部件，镜像坐标算错 | 统一用 W - x - w 计算镜像位置 |
| 4 像素的小球画成了方块 | 用了 ellipse | 改用字符画 |

“Genini” 是逐句把所有台词截图、拼成联系表以后才发现的。**任何文字和图形，最终都要以渲染出来的样子为准检查。**

## 其他教训

- **缓存的 key 要包含所有会影响画面的参数。** 有一次缓存只按 `frame % 2` 区分，但图里的天线灯是按 `frame % 4` 闪烁的，结果画面取决于“哪一帧先被画到”。
- **一切保持可复现**：固定步长、带种子的随机数、稳定排序。这样才能逐帧对比、做回归测试。
- **透明度只用 0 和 255**，导出前用 `stats` 检查。半透明像素在别的引擎里会被当成不透明，或者产生色边。
- **最终尺寸下也要看。** 联系表放大 6 倍看着很好的细节，原尺寸下可能糊成一团。
