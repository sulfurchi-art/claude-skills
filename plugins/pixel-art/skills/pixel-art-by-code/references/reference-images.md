# 把参考图转成干净的像素图

复杂的有机造型，比如动漫人物、头发、写实动物，很难只靠描述几何形体画好。用户给了参考图，或者有 AI 生成的“像素风”图时，更好的做法是把它**转换**成真正的像素图，再用代码修整和做差分。

## 什么时候需要转换

- **用户给的手绘图或立绘**：有明确的造型，要求还原。
- **AI 生成的“像素风”图**：看起来像像素画，其实不是。它的问题有三个：
  - 每个“像素”是边缘发虚的 N×N 色块；
  - 色块网格会漂移，并不对齐；
  - 颜色有几千种，相近色非常多。

  直接缩小会糊，必须先对齐网格、再统一颜色。
- **表情表**：同一个角色在多个格子里画了不同表情。需要逐格转换，并且所有格子共用一套调色板、一个对齐点。

## 步骤

1. **确认真实格式。** 扩展名不可信，`.png` 可能其实是 JPEG。先统一转成 PNG：

   ```bash
   ffmpeg -y -i in.jpg in.png
   ```

   `pixel.js` 只读 PNG。

2. **数出“美术像素”的大小 N**，也就是原图里一个像素块有几个屏幕像素。用 `node pixel.js view in.png --scale 4` 放大一小块来数，或者裁一块边缘清楚的区域，打印成字符看。

3. **裁掉无关部分**：标题、标签、边框。表情表要按格子切开：

   ```js
   const panel = P.load('sheet.png').crop(x, y, w, h);
   ```

4. **转换**：

   ```bash
   node pixel.js pixelate panel.png out.png --pixel 4 --colors 32
   ```

   处理过程：
   - 每格取内部的主色，忽略发虚的边缘；
   - 从边界开始洪泛填充，去掉背景（`--tolerance` 控制容差，默认 12）；
   - 用中位切分加 k-means 把颜色减到 `--colors` 种；
   - 去掉孤立的杂色格子。

   结果是 1:1 的像素图，同时生成一张放大预览 `_preview.png`。

5. **看预览，按情况调整**：

   | 现象 | 调整 |
   |---|---|
   | 轮廓被吃掉一块 | 背景和主体颜色太接近，调小 `--tolerance`；或者用 `--bg none` 保留背景，之后手工删除 |
   | 背景没去干净 | 调大 `--tolerance` |
   | 线条断开、细节糊掉 | 网格没对齐，用 `--offset x,y` 把网格移动 1~3 个像素再试；或者重新确认 N |
   | 颜色太少、渐变成了色块 | 调大 `--colors`（人物通常需要 24~48 色） |
   | 杂点太多 | 本身已默认去孤点，剩下的手工修 |

6. **手工修整**，这一步用代码完成：
   - `s.set` 改单个像素；
   - `s.stamp` 重画眼睛、嘴这类关键部位（用 `references/craft.md` 的五官库）；
   - `s.outline` 补齐断开的描边。

   修完打印成字符检查一遍。

7. **多帧（表情表）**：
   - **统一调色板**：先把所有格子拼成一张大图，一起 `pixelate`，再切开。这样每帧颜色一致。
   - **统一对齐**：以基础表情（neutral）为准，计算每帧的包围盒或特征点偏移，平移到同一个锚点。通常差 0~1 像素。
   - **最后检查**：用联系表并排检查，确认差分之间没有跳动。

## 局限与更强的做法

`pixelate` 用的是固定网格，适合网格基本规整的图，作为第一遍处理。

AI 图的网格漂移严重、或者杂色很多时，可以换用更强的方法：
- **逐行逐列拟合网格**：找到真实的色块边界，而不是假设等距；
- **只从“纯色像素”学习调色板**：排除边缘上的过渡色；
- **整体求解相邻格子**：做成一个马尔可夫随机场（MRF）问题，让相邻格子只在真正有边缘的地方才变色；
- **多帧共用基础**：所有帧共享一个基础图，每一帧只求解与它不同的部分。

无论用哪种工具，最后都要回到“看图 → 写下具体问题 → 改”的循环。

## 实例：鲸鱼女仆表情表

来源是一张 JPEG：6×2 个面板，每个约 256×400，约 4 个屏幕像素对应 1 个美术像素。处理流程如下：

1. 每个面板裁掉标签，只保留人物区域。
2. 2 倍面积降采样，回到美术像素尺度。
3. 从边缘洪泛填充，去掉纯色背景。
4. 保留最大的连通块，以及头顶的特效部件，去掉零星碎片。
5. 所有帧以 neutral 为准对齐，偏移不超过 1 像素。
6. 所有帧共用一个 36 色调色板。
7. 用 RLE 编码存成数据文件。

之后在游戏里把表情映射到对应的格子。表情表里没有的表情，就在已有格子上叠加特效生成，例如在“慌张”格子上加旋转的星星，做出“眩晕”。
